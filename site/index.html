What it does

How the marking works

You type the text and the rules place the marks: which syllable is held and for how long, where an accent falls, where a pause belongs, what an anusvāra becomes before a sibilant. Where a rule is wrong for a particular word you overrule it by hand, and that decision survives every later edit. It is stored against the letter rather than against the way the letter is drawn.

Different texts, different rules

A Ṛgvedic sūkta and a purāṇic stotra are not marked the same way. There are five registers: Taittirīya, Ṛgveda, Śukla Yajurveda, smārta and prose. Each document says which one it follows, and a section can say something different from the document it is in.

One to one with the Word file

The page on screen is the page that prints. The sizes, leading, indents and margins are taken from the Word documents this program was built to replace, and a test measures the rendered page against them on every build.

Three ways to look at it

A continuous column for writing, real pages for checking what the PDF will be, and a wide view that shows how the text will read on the web. All three draw the same document with the same marks, so the lines do not move when you switch.

A recitation against the text

Open a recording and the program works out which second of it is which pāda, by listening for the breaths and counting syllables. The line then lights up as it is sung, and clicking a line plays it.

What was copied stays copied

A verse transcribed from a hand-marked page is a record of what somebody wrote. Its marks exist nowhere else, so every marking says whether a person or the engine placed it, and the rules only run when you ask them to.

Devanāgarī, Telugu and Tamil

The same marked text in four writing systems. The other three are derived from the first rather than typed again, so a correction is made once.

Inside Microsoft Word

The same marking, in a Word document

A lot of this text already lives in Word files, and moving a document between two programs to mark it is not a workflow anybody keeps up. So the marking runs inside Word: put the caret in a line, press Short or Long, and the box Word draws is the box śikṣāmitra prints — the same style sheet, to the eighth of a point.

It edits the document, not a copy

Holdings, accents, the reading aids and the pauses, applied to the paragraph the caret is in. Nothing is exported and nothing is imported; the file stays a .docx and stays yours.

A blank document, set up in one press

A marking is a style in Word, and a new file has none of them. Add the styles puts all sixteen in and leaves nothing visible behind; Insert a specimen puts in a short block that uses each one with its name beside it, to read once and delete.

It reads what is already marked

A document marked by hand years ago is read as it stands — the marks are transcribed from the styles that are there, never recomputed. If the pane finds something it cannot account for, it says so and refuses to write rather than lose it.

The rules, when you ask for them

Choose a register and run the rules over the selection or the whole document. Marks placed by hand are kept unless you say otherwise, and the pane says how many it could not carry.

Word on Windows, Mac, iPad and the web

The pane uses only the parts of Word's API that exist everywhere — Word 2019 and later on the desktop, Word for Mac, Word on the web and on iPad. The box is a character border, which is what Word draws natively rather than a picture of one.

Nothing leaves the machine

The pane is a static page with no server behind it. It sends your text nowhere, stores nothing, and can be served from your own computer if you would rather not load it over the internet.

Installing it

It is not in Microsoft's store yet — that is a submission with an identity check behind it, and it is in hand. Until then it installs the way every Office add-in installs before it is listed: you point Word at one small file.

1

Save the manifest. manifest.xml — about 6 KB. Put it in a folder of its own, anywhere; a folder called WordAddins in your Documents is fine.

2

Tell Word about the folder. Windows: File → Options → Trust Center → Trust Center Settings → Trusted Add-in Catalogs. Paste the folder's path, press Add catalog, tick Show in Menu, then OK and restart Word.
Mac: there is no catalog — put the file in ~/Library/Containers/com.microsoft.Word/Data/Documents/wef and restart Word.

3

Open it. Insert → My Add-ins → Shared Folder → śikṣāmitra. It then has its own Marking button on the Home tab, and stays there.

Word on the web takes the same file: Home → Add-ins → Upload My Add-in. For a whole organisation, a Microsoft 365 administrator can deploy it to everybody at once from the admin centre's Integrated apps page, using the same manifest — nobody has to install anything.

Rather not load it from the internet? The pane is static, so it can be served from your own machine. npm run word-addin:certs once, then npm run word-addin:serve and npm run word-addin:install -- --host local. Nothing then leaves the computer at all.

Its own files

Its own file format

Once installed, śikṣāmitra owns .smdoc files and gives them their own icon. A document is JSON: one text per verse and a list of markings over it, which you can read without this program. Version 2 reads version 1 documents, and the format's rule is that a reader may not be broken by a writer it has never met.

It also reads and writes Word files, prints to PDF, and makes .vuchant packages that carry a document together with its recordings and pictures.

For agents and scripts

The command line does the same things

The window and the command line call the same code, so neither can gain something the other lacks. No command writes to a file unless you pass --write. 

sm import durga.docx --out durga.json      # a marked Word file, read
sm set-register durga.json --preset rigveda --write
sm hold durga.json --verse v-2 --units 0-4 --value long --write
sm audio map durga.json --file take.wav --write
sm export durga.json --out durga-out.docx
